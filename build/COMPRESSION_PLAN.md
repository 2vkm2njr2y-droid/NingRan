# 无损压缩与加密实现计划

## 目标

- 保留 `.nr` 文件的外部使用方式、媒体传输协议和播放器调用方式。
- 在加密前按独立分段尝试 Zstandard 无损压缩；压缩结果不比原始数据小时，保存原始分段。
- 保留按位置读取能力，视频拖动和预览图不需要导出完整明文文件。
- 新建加密文件和修改已有加密文件使用同一个压缩等级。

## 压缩等级

| 界面名称 | Zstandard 策略 |
| --- | --- |
| 存储 | 不压缩 |
| 最快 | 低压缩等级，优先加密速度 |
| 标准 | Level 5，速度与体积平衡 |
| 最大 | 高压缩等级，优先减小体积 |

每个逻辑分段都会比较原始长度与压缩长度，选择较小者进入加密容器。

## 数据布局

外层归档头、密码派生、身份签名和媒体管道保持不变。内部索引增加压缩标记、原始长度、保存长度和物理位置，数据记录改为可变长度，并继续让每个记录独立认证加密。旧版本不要求识别新格式。

## 读取路径

播放器仍发送原来的起点和长度请求。会话根据索引定位相关分段，解密并解压后返回原始媒体字节；预读缓存继续工作，且不创建明文临时文件。

## 验证

- 单元测试覆盖四个压缩等级、压缩无效时回退原文、随机定位和完整导出。
- 编译检查核心库和 Windows 客户端。
- 运行现有测试，重点检查媒体播放器、预览图和加密文件修改流程。
